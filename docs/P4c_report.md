## 2. 候选权衡与选型

| 候选 | 结论 | 理由 |
|---|---|---|
| ① 按句长逐句改字号 | 落选（只留作极端兜底） | 能放下，但字号每句都在跳，跟读时很突兀 |
| ② 卡片高度逐句自适应 | 落选（改为按篇恒定，见⑥） | 每换一句，下方列表就上下跳一次 |
| ③ 卡片内按进度自动滚动 | 落选 | 时间轴已推迟，句内进度只能估算；滚动本身分散注意力，译文也露得晚 |
| ④ 长句二次断行展示 | 落选 | 总高度降不下来，而且容易被理解为改了切分 |
| ⑤ 调整译文位置或占比 | 落选 | 手机宽度下问题出在原文行数本身；译文保持 0.68 倍 |
| **⑥ 组合：按篇量测、篇内恒定** | **采用** | 见下 |

⑥ 的具体做法：
- 装入一篇文章时，在一个离屏量测盒里（与卡片同宽、同样式、同一份 ruby HTML，假名和译文的显隐状态也一致）渲染全篇每一句；
- 用二分法找出「最高的那句也能放进卡片上限」的**最大整数字号 f**（不低于下限）；
- **卡片高度 = 最高句在 f 下的实际所需高度**；**列表高度 = 总预算 − 卡片高度**。总预算等于原来的 `--card-h + --list-h`，所以整页版面不变；
- 篇内所有句子共用同一个 f 和同一个卡片高度，所以**连播跨句时卡片和列表的位移都是 0**；
- 只在换篇、旋转或缩放、切换假名、切换译文显示/隐藏时重算。用户主动操作引起的变化，或者换篇时的变化，是可以接受的。
- 短篇（对白）能用更大的字号和更矮的卡片，列表因此变高；长篇则统一稍小一点。

## 3. 参数与公式

- **总预算**：手机（宽度 <1000px）为 0.68×视口高，宽度 ≥1000px 为 0.74×视口高。
- **卡片上限**：总预算 − 列表最小高度 − 10px。列表最小高度为 180px（宽度 ≥1000px 时另外不少于 0.2×视口高）。卡片最少 120px。
- **字号**：基准沿用现有 `--fs-card`（手机 22–28px，1000–1279px 为 28px，电视 40–56px）。
  - **下限**：手机 19px（假名 rt 约 9.5px，仍然可辨，再小就难认了）；桌面 20px；电视（≥1280px）32px（3 米外可读，对齐 v2「≥30px」的口径）。
- **矮屏兜底顺序**：
  1. 先把字号降到下限；
  2. 还放不下，就让卡片向列表借高度（列表最少保留 110px，大约 3 行），字号仍然整篇统一；
  3. 还放不下的极端长句，才单句再缩字号，绝对下限 15px。
- 实现只用 `offsetHeight`、`getComputedStyle` 和内联 CSS 变量；**没用 `:has`、容器查询、`text-wrap: balance`**，照顾 webOS。
